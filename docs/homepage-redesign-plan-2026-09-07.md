# Coolbat 个人主页改造实施方案

日期：2026-09-07。版本：v1.1，开发规格归档。执行状态：首版开发与本地验收已完成，详见 [开发与验收记录](homepage-implementation-2026-09-07.md)。

依据：用户提供的「Coolbat · 观星造物」效果图，以及改造前仓库的页面、组件、样式和内容配置。下文保留制定方案时的现状、建议和任务拆解；其中「当前」「尚未」等表述描述的是规划阶段。实际实现、验证结果与内容边界以开发记录为准。

## 1. 改造目标与范围

把首页升级为以个人品牌和作品为主的入口，让访客依次了解：你是谁、做过什么、正在探索什么、最近写了什么。主要行动是查看作品，次要行动是阅读文章、了解作者和访问社交主页。

默认假设：首页中文优先；桌面端以效果图为构图基准；手机端重新编排；项目和文章使用真实内容。效果图中的英文作为简短辅助文案，完整英文站属于后续独立需求。

首版范围包含首页、共用导航和页脚、项目卡片及数据、必要的全站字体与主题适配。文章、搜索、标签、归档和关于页保留现有地址，阅读页继续采用适合长文的窄栏。关于页的模板介绍应替换为真实个人介绍。

## 3. 效果图的设计语言

核心是深墨色背景、细金色星轨、暗部山水、宋体标题与克制留白共同形成的东方观星意象。

建议保留的特征：左文右图的首屏；星图超出局部容器的构图；山水横贯首屏底部；四张横排作品卡；下方「当前轨道 / 最近写作」双栏；细分隔线与少量竖排题字。

网页化时需要调整：提高小字和正文亮度；把主要导航补充清楚；放大手机文字和点击区域；允许自然向下滚动。效果图约 1448 × 1086，常见笔记本的可用高度更小，页面高度应由内容决定。

建议的初始视觉参数，最终以浏览器对照为准：

| 项目 | 建议值 |
| --- | --- |
| 背景 / 卡片底色 | `#080F14` / `#10171D` |
| 主文字 / 次文字 | `#E8E4DA` / `#A9ADA9` |
| 强调色 | `#B9A47B`，用于主要星点、焦点和少量边框 |
| 装饰线 | 金灰色低透明度；交互控件边界独立验证可辨识度 |
| 中文标题 | 有授权的宋体，例如思源宋体；采用本地 WOFF2 子集 |
| 正文 | 系统中文字体栈，英文搭配衬线展示字体；等宽字体保留给日期、编号和代码 |
| 字号 | 桌面主标题约 52–64px；手机 32–40px；正文 16–18px；内容辅助字约 14px |
| 容器 / 留白 | 最大宽度约 1320–1360px；桌面左右约 48px，手机约 20px |
| 卡片 | 1px 细边框、0–2px 圆角、约 20px 间距 |

正文对比度目标至少 4.5:1，大字至少 3:1；图片叠加区按实际合成背景测量。参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

## 4. 页面结构与用户路径

| 模块 | 桌面布局与内容 | 主要行为 |
| --- | --- | --- |
| 顶部导航 | 左侧 coolbat.xyz 与短标语，右侧作品、写作、关于、搜索、主题开关 | 对应 `/projects/`、`/posts/`、`/about/`、`/search/` |
| 首屏介绍 | 约 42% 文案、58% 星图；标题「Coolbat · 观星造物」、两行介绍、一句英文、主要按钮 | 「探索我的作品」滚动到首页作品区 |
| 精选作品 | 真实项目最多四张；封面、名称、一句话用途、标签、箭头 | 整张卡片访问真实项目地址；更多作品到 `/projects/` |
| 当前轨道 | 小型轨道图、三个探索方向、简短说明、最近更新日期 | 首版作为静态近况内容，无须制造多余可点击元素 |
| 最近写作 | 最多四篇，标题、短摘要和真实日期 | 文章进入原详情地址；更多文章到 `/posts/` |
| 页脚 | 品牌短句、版权、已有社交链接和 RSS | GitHub、X、YouTube、`/rss.xml` |

首屏介绍可先使用效果图中的表达作为待定文案：「一个独立开发者，在 AI、交互与文化的交汇处，探索技术与人文的更多可能。」

「当前轨道」可先拟为 AI 原生产品、交互与可视化、东方美学的数字表达，交付前需与真实近况对齐。

最近写作继续复用现有内容读取和草稿过滤逻辑；首页按发布日期倒序取四篇，精选标记不会使文章从列表中消失。现有工具默认优先按修改日期排序，首页需明确自己的规则，避免日期含义混淆。

## 5. 星图与山水的制作方案

首屏分成四层，各层独立制作和调节：

1. CSS 深色背景与局部柔光，承接整体色调。
2. 独立山水背景图：压缩后的 WebP/AVIF，提供桌面和手机裁切，边缘渐隐融入底色。
3. 内联 SVG 星盘：轨道、刻度、星座连线、主星和稀疏背景星点，坐标固定、可缩放。
4. HTML 文案与星名标注：保留可选择文字和响应式控制，重点标签与图案分别定位。

星图作为品牌插画人工编排。轨道和连线固定，少量星点可做亮度呼吸；标题和星名保持稳定。首版以静态构图校准为先，再增加动效。

SVG 为装饰时使用 `aria-hidden`；有业务信息的文字留在 HTML。星图背景不接收指针事件，避免遮住按钮。首页不依赖星图交互传递必要内容。

素材清单：一套山水背景及手机裁切、一份主星图 SVG、一份复用的小轨道图、真实项目封面、字体子集、首页分享图。若只有当前效果图，需要单独重制山水素材和星图；成品页面中的文字使用网页排版。项目封面采用真实截图或对应作品原图，通过统一比例、边框和轻度色彩调整保持一致。

## 6. 响应式、主题与动效

| 宽度 | 排版策略 |
| --- | --- |
| ≥1280px | 左文右图；作品四列；下方双栏 |
| 768–1279px | 星图缩小并减少外围标注；作品两列；下方空间不足时上下排列 |
| <768px | 介绍在前、简化星图在后；作品单列；当前轨道和文章依次排列；导航折叠 |

手机端主标题、介绍和作品按钮优先可见，星图控制高度；省略竖排题字与装饰性英文，必要信息仍保留。文章标题允许换行，日期不挤占标题宽度。按钮与菜单以约 44px 可点击高度设计。

主题建议：暗色作为首次访问的品牌默认表现，已有用户主题选择优先；保留浅色切换，使用宣纸白、墨色文字和深金色线条。两套主题复用组件，分别调节山水与星图对比度。检查跨页切换与刷新，避免主题闪烁和重复事件绑定。

动效控制在三类：首屏短暂淡入、少量星点呼吸、链接/卡片的约 180–250ms 反馈。卡片最大约 2px 上移，箭头少量位移。支持 `prefers-reduced-motion`，关闭持续运动；无 JavaScript 时主要内容直接可读。

首页设置唯一 H1、中文描述和正确 canonical；首页采用 WebSite/Person 信息，文章页保留适用的 BlogPosting 数据。原文章路径、RSS 和 sitemap 在改造后逐项验证。

## 8. 内容准备与缺省状态

每个精选项目需要：名称、一句话价值描述、真实地址、封面、2–3 个标签、当前状态。效果图中的墨问、星图笔记、云山集、TidyFlow 暂视为设计示意，不能据此认定为已有作品。

项目不足四个时显示实际数量并调整网格；没有可公开作品时显示简短准备中说明。文章不足四篇时显示实际数量；没有真实文章时显示自然的写作预告，不生成虚构文章标题、发布日期或空链接。模板文章的展示与旧地址处理分别决定，避免未经核实删除可能已经被访问的地址。

交付前还需确定：精选项目清单、三条真实近况、最终自我介绍，以及可使用的山水和项目封面素材。这些是内容输入项，方案本身可以先行评审。

## 9. 实施顺序与交付物

按一名熟悉项目的开发者、内容和素材基本就绪估算，总体约 4–6 个工作日；素材重制和反馈轮次会影响实际时间。

| 阶段 | 工作 | 可评审交付物 | 估算 |
| --- | --- | --- | --- |
| A | 确定真实内容、视觉参数和素材方案；记录当前构建基线 | 文案表、素材清单、桌面与手机布局草图 | 0.5–1 天 |
| B | 调整容器与字体，完成桌面静态首屏和主星图 | 1440px 桌面首屏截图及参考图对照 | 1–1.5 天 |
| C | 完成作品、当前轨道、写作、页脚和内容读取 | 使用真实数据的完整首页 | 1 天 |
| D | 完成移动端、浅色主题、动效、字体与图片优化 | 手机和平板截图、主题与交互演示 | 1–1.5 天 |
| E | 检查构建、视觉、可访问性、原有路由及预览环境 | 验收记录、预览页面和已知限制 | 0.5–1 天 |

桌面首屏的构图和素材质量应先通过评审，随后扩展其余页面。需要在线上线发布时，以通过验收的具体预览版本作为发布对象。

## 10. 验收标准

- 视觉：在约 1440px 宽下对照效果图，分别检查大区块比例、星图尺寸与位置、山水融合、字体、边框及卡片；另检查 1440×900 的真实笔记本视口。视觉结果由截图对照判断。
- 响应式：检查 375、390、768、1024、1440px 宽，无横向溢出、标题截断和星图遮挡。
- 内容：真实项目、状态、日期和链接；零模板内容冒充个人成果；文章列表数量少时仍成立。
- 功能：主页按钮、项目、文章、搜索、标签、归档、关于、RSS、菜单和主题切换逐项可用；覆盖直接打开、站内跳转和返回。
- 可访问性：键盘顺序清楚，焦点可见，跳到正文有效；正文与大字对比度达标；装饰图与内容图正确标注；减少动效设置有效。
- 工程：安装锁文件依赖后先记录基线；执行项目已有 lint、format:check、build，并补充 Astro 类型检查。旧问题与本次引入的问题分开记录。
- 性能：为图片设置尺寸，优先加载必要的首屏资源，后续图片按位置延后；按实际压缩结果控制素材体积。以 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 为优化目标，依据 [Core Web Vitals 阈值说明](https://web.dev/articles/defining-core-web-vitals-thresholds)。本地实验室数据与上线后的真实用户第 75 百分位结果分别记录。
- 发布：预览构建与正式发布分别验证；正式发布后检查首页、代表性文章、资源和元数据。GSC 收录及流量变化属于后续观测。

## 11. 首页文案草案与内容取舍

以下为可用于首屏排版的文案草案，项目与近况仍需使用真实资料。

| 位置 | 推荐文案 | 使用规则 |
| --- | --- | --- |
| 顶部标语 | 以技术为舟，循星而行 | 宽度不足时隐藏标语，保留站名和导航 |
| 首屏引言 | 仰观天文，俯察万物 | 桌面可展示；手机优先保留主体介绍 |
| 主标题 | Coolbat · 观星造物 | 一个 H1，允许两个 span 控制断行 |
| 主介绍 | 我是 Coolbat，一名独立开发者。探索 AI、交互与文化，也把想法做成可以使用的作品。 | 比效果图的表述更具体，作为推荐草案 |
| 英文辅助 | An independent developer exploring AI, interaction, and culture. | 桌面展示，手机可省略；英文片段标记 lang=en |
| 主要按钮 | 探索我的作品 → | 链接到 #featured-works |
| 作品区 | 精选作品 / Featured works | 有更多项目时显示「全部作品」 |
| 近况区 | 当前轨道 / Now | 方向与更新日期分开维护 |
| 写作区 | 最近写作 / Latest writing | 显示真实发布日期 |
| 页脚 | 独立开发 · 自由探索 · 长期创造 | 与已有社交入口并列 |

近况候选文案为：

- AI 原生产品：把新的模型能力，变成具体可用的工具。
- 交互与可视化：探索更直观的表达，让复杂信息更容易理解。
- 东方美学的数字表达：用网页、图像与交互，重新表达山水与星空。

这些表述只作为草案，不表示相关产品已经完成或上线。首屏通过作品体现能力；成长经历、工具栈和长篇自述放在关于页与文章中。

## 12. 布局尺寸与响应式细则

桌面起始标尺使用 1440px 视口、左右 48px 留白、1344px 内容宽度。实际采用流式尺寸，1360px 为容器上限。下面的高度均为起始范围，内容变长时自然撑开。

| 模块 | 桌面规格 | 手机规格 |
| --- | --- | --- |
| Header | 高约 76–80px；站名 28px；导航 14–16px | 高约 64px；站名 22px；主题和菜单各约 44px 热区 |
| Hero | 高约 420–470px；文案可用宽约 520–550px；星盘直径约 600–680px | 内容宽为视口减 40px；介绍结束后放置约 220–280px 高的简化星图 |
| Hero 标题 | 56–60px 起调，行高 1.15；空间不足主动换行 | 34–38px 起调，「Coolbat」与「观星造物」可分两行，断行时隐藏分隔点 |
| Hero 正文 | 18px、行高 1.75；与标题间距约 20px | 16px、行高 1.75；保持自然断句 |
| 主按钮 | 高约 44px；宽约 168–184px；距介绍约 24px | 保持至少约 44px 高，以内容宽度为准 |
| 区块标题 | 中文约 26px、英文约 12–13px；分隔线自动填满剩余空间 | 中文约 22px；空间不足省略英文，保留「更多」入口 |
| 四列作品卡 | 约 321px 宽、20px 间距；封面约 3:1；整卡通常 240–280px 高 | 单列；封面约 16:7；项目截图按内容决定裁切焦点 |
| 下方双栏 | 约 56:44，间隔约 40px，中央细分隔线 | 当前轨道在前、文章在后；移除中央竖线 |
| 区块间距 | 约 40–56px | 约 32–40px |

在 1024–1279px 保持简化的左文右图；768–1023px 首屏改为上下排列，避免标题与星图互相挤压。作品区从 1280px 起四列，768–1279px 两列，768px 以下单列。下方双栏从 1024px 起启用。

## 13. 视觉素材的可执行规格

### 星图

建议 SVG 使用 `viewBox="0 0 1000 1000"`，人工排布约 5–7 道主要轨道、6–8 个重点星点、少量星座连线、120–180 个背景星点。这些数量是制作起点，静态视觉检查后可以删减。

将 SVG 分为轨道、刻度、连线、背景星点、主星五组。主星可用重复的小范围光晕，避免为每个星点添加昂贵的模糊滤镜。轨道粗细随最终显示尺寸校准，主星与背景星点的亮度形成明显层次。

星名的坐标与对应主星使用同一个归一化坐标系。标签层与 SVG 放在同一正方形容器里，让两者使用一致缩放与裁切，防止文字与星点脱离。每个标签可设置桌面/手机显隐规则和局部偏移。外围竖排文字只存在于宽屏版本。

星图画布允许在首屏艺术区域内裁切；正文区、按钮和导航区设置清晰的避让范围。层级按背景 0、山水 1、星图 2、文案 3、导航菜单 4 组织，焦点轮廓不能被裁切。

### 山水与项目封面

| 素材 | 制作输入与导出 | 初始传输预算 |
| --- | --- | --- |
| 桌面山水 | 约 2400×900 原始素材；远山层叠、雾带、暗部山脊，左侧低细节，文字区域保持平静 | 浏览器实际选用版本约 200–350KB |
| 手机山水 | 从同一素材独立裁切约 900×900，检查主山脊位置 | 约 80–160KB |
| 主星图 | 固定坐标 SVG，构建期生成或静态存储 | 压缩传输约 20–50KB |
| 项目封面 | 每个真实项目独立素材；通常提供 640px 与 960px 宽版本 | 每张浏览器选用版本约 50–100KB |
| 中文标题字体 | 本地 WOFF2，仅覆盖本版固定标题；动态标题缺字时有明确回退字体 | 所有首屏字体合计争取 ≤180KB |
| 分享图 | 1200×630，站名、主标题与简化星盘，留足边缘安全区 | 按实际清晰度压缩；无需首屏下载 |

以上是项目预算，不是已经测得的结果。首屏资源合计以约 1MB 压缩传输为起始控制目标；在图片必要细节与体积冲突时先调整尺寸和构图。桌面与手机资源按条件选择，避免两套同时下载。

山水素材制作 brief：横向东方山水夜景，深墨蓝色调，远山与薄雾层叠，山脊集中在画面下半部，左侧留出安静暗部，右侧允许较丰富的山势，边缘自然融入纯暗背景。文字与星盘通过页面单独叠加。

字体加载使用清晰的回退字体并配置 `font-display`；采用 swap 时需要检查替换字体带来的尺寸变化。子集字体只用于固定展示文字，文章正文和动态内容使用覆盖完整的字体栈。参考 [MDN font-display](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@font-face/font-display)。

## 14. 数据结构与显示规则

以下是实现接口草案，尚未写入源码。

```ts
// src/data/home.ts 的数据结构建议
type HomeContent = {
  hero: {
    eyebrow?: string;
    title: string;
    introduction: string;
    englishIntroduction?: string;
    cta: { label: string; href: "#featured-works" };
  };
  currentOrbit: {
    updatedAt?: string; // 实际修改近况的日期；未提供则不显示
    items: Array<{ id: string; title: string; description: string }>;
  };
};

// 在现有 Project 必填字段上增加可选字段
type ProjectPresentation = {
  id?: string;
  featured?: boolean;
  order?: number;
  status?: "live" | "beta" | "archived";
  imagePosition?: string;
};
```

项目规则：保留现有 `title/description/link/image/tags` 字段。首页只选择显式 `featured: true` 的项目，按 order 升序排列并取前四个，未配置 order 的排在后面。同序号保持原数据顺序。状态未提供时不显示状态；有真实可访问地址的测试版可以注明 Beta。尚无地址或封面的候选作品留在内容待办表中。

为避免内容较少时卡片过宽，桌面有 1–2 个项目时采用两列上限且单卡最大约 520px；3 个时三列；4 个时四列。平板最多两列，手机单列。零项目时展示「作品正在整理中」的简短状态，保留作品区锚点，隐藏无实际目标的更多入口。

文章规则：读取现有 blog collection → 排除不符合首页展示条件的内容 → 按 pubDatetime 倒序 → 取前四篇 → 使用原 slug 生成链接。日期以 Asia/Shanghai 格式化为 YYYY.MM.DD，并保留机器可读的 time datetime。标题、排序和日期均以发布口径为准。

当前 `Datetime.tsx` 优先显示修改日期，首页应使用独立的精简日期展示或增加明确日期模式，避免直接复用后出现口径不同。文章详情和归档的既有排序、时间展示由原页面继续管理。

为保留模板文章旧地址，同时将其从个人首页移除，可在内容 schema 增加 `showOnHome` 可选字段，默认 true，对示例文章显式设置 false。这个字段只控制首页，不等于删除文章或从 RSS、搜索中隐藏它；这些位置的模板清理由发布前内容检查统一决定。

当前 `postFilter` 在开发模式允许预览未来文章，生产环境还配置了 15 分钟时间余量。首页发布检查必须在生产构建预览中执行，并记录是否沿用这条既有策略；严格定时发布属于单独的内容发布策略调整。

## 15. 组件边界与旧页面兼容

| 组件 | 输入与职责 | 兼容方式 |
| --- | --- | --- |
| Layout | 增加可选 presentation: reading/showcase；负责 body 标识、元数据和主题基础 | 默认 reading，现有页面无需逐页改参 |
| Header / Footer | 增加可选宽版样式；导航地址和社交数据继续共用 | 首页使用宽版，阅读页使用原阅读容器 |
| Main | 增加可选 width: reading/wide，管理非首页内容宽度 | 默认 reading；项目列表可显式选择 wide |
| Hero | 介绍、主按钮、背景与星图的总体构图 | 内容直接生成 HTML |
| StarMap | 接收尺寸模式和唯一 id 前缀；管理纯视觉元素 | 多实例时 SVG defs/filter 的 id 必须唯一 |
| FeaturedWorks | 只接收筛选后的项目，控制数量对应的网格 | 卡片使用现有 ProjectCard 扩展后的视觉版本 |
| CurrentOrbit | 近况数据、小轨道插画、实际更新时间 | 文本独立于装饰图可读 |
| LatestWriting | 已筛选和排序的文章数据 | 使用原文章链接，保持首页日期口径 |

样式迁移先为首页添加明确的 presentation 标识与布局覆盖，保留旧页面的默认表现，再逐项缩小通用选择器的作用范围。对插画 SVG 增加专用标记，明确覆盖图标尺寸与默认 fill，检查其内部 path/circle 的继承结果；不要一次性取消所有旧图标依赖的基础样式。

Header 的折叠菜单采用内联展开面板：打开时更新 aria-expanded；Escape 关闭并将焦点归还菜单按钮；选择导航后关闭；不使用无必要的模态焦点锁。主题按钮提供「切换到浅色/深色」的动作名称。

首页锚点设置适当 scroll-margin；键盘启动主按钮时，滚动后阅读和焦点顺序应能自然继续进入作品区。卡片只有一个主要链接，内部标签为文本，避免嵌套链接。

## 16. 主题与动效状态表

两套主题建议使用以下独立色值：

| 角色 | 暗色 | 浅色 |
| --- | --- | --- |
| 页面背景 | `#080F14` | `#F4F0E7` |
| 主文字 | `#E8E4DA` | `#292D2B` |
| 次文字 | `#A9ADA9` | `#62675F` |
| 文字强调色 | `#B9A47B` | `#75613D` |

按纯色 sRGB 计算，暗色主文字与背景对比度约 15.19:1、次文字约 8.48:1；浅色主文字约 12.27:1、次文字约 5.09:1。这只是候选色值校验，图片、透明度和叠加后的实际页面仍需单独测量。浅色的山水与星图分别调节颜色和强度，文字强调色使用较深的金棕色。

| 场景 | 预期行为 |
| --- | --- |
| 首次访问，无存储偏好 | 使用品牌默认暗色 |
| 已保存浅色/深色选择 | 尊重保存值；刷新和跨页保持 |
| 存储不可用或保存值无效 | 使用默认暗色，页面和开关仍可正常工作 |
| 系统主题发生变化 | 在本方案的固定默认+手动切换模式下，不覆盖用户选择 |
| Astro 站内切换 | 换入页面继承当前主题；新按钮正确绑定且每次只触发一次 |
| 开启减少动效 | 关闭星点呼吸、入场位移和装饰动画；主要内容立即可见 |
| JavaScript 禁用 | 文字、作品、文章和直接导航保持可访问；菜单提供可用的静态回退 |

目前主题脚本的系统变化监听会写入并覆盖主题；需要按上表重新明确策略。主题在首屏绘制前设置，并与 Astro 页面切换生命周期协调。参考 [Astro 4 View Transitions](https://v4.docs.astro.build/en/guides/view-transitions/)。

| 动效 | 建议参数 | 终止与回退 |
| --- | --- | --- |
| 首屏介绍出现 | opacity 与最多 8px 位移，约 400–600ms | 内容默认可见，增强成功才运行动画 |
| 主星亮度呼吸 | 约 4–6 秒一周期，最多 3–5 颗主星 | 减少动效时固定亮度；提供暂停持续动效的可访问控制 |
| 卡片 hover | 上移约 2px、边框略提亮，约 200ms | 触屏用按压/焦点反馈，必要信息无需悬停 |
| 箭头 | 横向移动约 3px，约 180ms | 减少动效时只改变颜色 |
| 页面切换 | 延续轻量淡入淡出 | 首页主星图无需复杂跨页变形 |

减少动效通过 `prefers-reduced-motion` 读取用户偏好，运行中变化也应响应。参考 [MDN prefers-reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)。
